# 병원 블로그 글 생성기

질환 키워드 하나를 넣으면, 사람들이 실제로 검색하는 세부 주제를 찾아주고, 최신 논문을 근거로
원장이 직접 쓴 듯한 네이버 블로그 칼럼을 만들어 주는 도구입니다.

```
키워드 입력 (예: 허리디스크)
 → 네이버 자동완성으로 실제 검색어 수집 (+ 검색광고 API 월 검색량, 선택)
 → Claude가 세부 주제 3개 추천 + 주제별 PubMed 영문 검색식 생성
 → 원장이 주제 하나 선택
 → PubMed 최근 3년 리뷰·임상연구 3편 검색, 초록 요약
 → (동시에) 네이버 블로그 상위 5개 글 분석 → 분량·키워드 횟수·사진 수 기준, 추천 제목
 → Claude가 칼럼체 블로그 글 작성 (H1/H2/H3 HTML, 사진 자리 표시)
 → 완성 글 vs 상위글 기준 점수표
 → "블로그용 복사" 버튼으로 네이버 스마트에디터에 서식째 붙여넣기
```

결과물 예시는 [`samples/`](samples/) 폴더에 있습니다.

## 실행 방법 (Windows)

```bat
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
copy .env.example .env
start.bat
```

`start.bat`을 더블클릭하면 서버가 켜지고 브라우저에 http://localhost:8000 이 열립니다.

### 필요한 것

| 항목 | 필수 여부 | 비용 |
|---|---|---|
| [Claude Code](https://claude.com/claude-code) 로그인 **또는** `ANTHROPIC_API_KEY` | 둘 중 하나 필수 | 구독 안에서 무료 / API는 글 한 편 약 $0.08 |
| 네이버 검색광고 API 키 | 선택 (없으면 검색량 없이 동작) | 무료 |
| PubMed (NCBI) | 키 없이 동작 | 무료 |

`.env`에 `ANTHROPIC_API_KEY`가 비어 있으면 이 PC에 로그인된 Claude Code(`claude -p`)로 글을 씁니다.
키를 넣으면 자동으로 Anthropic API를 씁니다.

## 폴더 구조

```
main.py                     FastAPI 서버 (/api/subtopics, /api/generate)
services/
  keyword_pipeline.py       네이버 자동완성 → 세부 주제 3개 + PubMed 검색식 추천
  naver_keyword.py          네이버 검색광고 API (연관 키워드, 월 검색량)
  benchmark.py              네이버 블로그 상위 5개 글 분석 → 분량·키워드·사진 기준 + 추천 제목
  pubmed.py                 PubMed 논문 검색 + 초록 요약
  generator.py              칼럼 작성 프롬프트, Claude 호출 (API 또는 Claude Code)
static/index.html           대시보드 화면
samples/                    생성 결과 예시
start.bat                   더블클릭 실행용
```

## 만든 과정

코딩을 모르는 사용자가 Claude Code와 대화하며 하루 동안 만든 프로젝트입니다.
단계마다 무엇이 문제였고 어떻게 바꿨는지 기록합니다.

### 1단계. 기본 파이프라인

처음 요청은 다섯 가지였습니다.

1. FastAPI 백엔드 + HTML 프론트엔드 폴더 구조, `requirements.txt`, `.env.example`, `main.py`
2. 네이버 검색광고 API 모듈(`naver_keyword.py`), PubMed 최근 논문 3편 초록 수집·요약 모듈(`pubmed.py`)
3. Anthropic SDK로 H2/H3가 있는 환자 친화적 블로그 글을 쓰는 `generator.py`
4. `/api/generate` 엔드포인트와 키워드 입력·글 복사 대시보드
5. 서버를 직접 실행해 보고 에러 수정

이 단계에서 정한 것:

- **의료광고법 준수를 프롬프트에 넣음.** 완치·100%·최고 같은 표현, 병원 비교, 치료 후기 형식을 금지하고,
  논문에 없는 수치를 지어내지 못하게 함.
- **논문 요약은 LLM을 쓰지 않음.** 구조화된 초록의 결론(CONCLUSIONS) 부분을 쓰고, 없으면 마지막 문장들을 씀.
  어차피 글을 쓸 때 Claude가 다시 가공하므로 호출을 한 번 아낌.
- **일부가 실패해도 글은 나오게 함.** 네이버 키가 없거나 PubMed가 실패하면 그 자료만 빼고 쓰고, 화면에 경고로 알림.
- **"블로그용 복사"는 `text/html`로 클립보드에 넣음.** 네이버 에디터에 붙여넣으면 제목·소제목 서식이 유지됨.

### 2단계. 무료로 돌리기

API 키가 없어서 실제 글 생성을 테스트할 수 없었습니다. 사용자는 "다 무료로 진행하고 싶다"고 했습니다.

- Anthropic API는 별도 결제라서, 이미 쓰고 있는 **Claude Code 구독을 헤드리스 모드(`claude -p`)로 호출**하도록 바꿈.
- `--tools ""`, `--setting-sources project`, `--disable-slash-commands`, `--strict-mcp-config`로
  사용자 PC의 플러그인·훅이 글에 섞이지 않게 막음.
- API 키를 넣으면 자동으로 API로 바뀌게 두 경로를 모두 남김.
  화면에 "API였다면 약 $0.08"을 보여줘서, 나중에 API로 바꿀지 판단할 수 있게 함.

### 3단계. 논문 검색 품질

첫 실행에서 "허리디스크" 글에 관련 없는 **뼈 종양 증례보고**가 참고 논문으로 들어왔습니다.
최신순으로만 정렬했기 때문입니다.

- **최근 3년 · 리뷰/메타분석/임상시험 · 관련도순**으로 바꿈.
  이후 세계신경외과학회 권고안, 체계적 문헌고찰, 운동치료 메타분석이 잡힘.

### 4단계. 보고서체에서 칼럼체로

사용자 피드백: "글은 좋은데 너무 보고서 형식이고, AI 티가 너무 난다."

- **화자를 "진료가 끝난 저녁에 칼럼을 쓰는 원장"으로 바꿈.** 1인칭, 의견을 분명히, 구어체("~거든요", "~더라고요").
- **AI 티 나는 표현을 구체적으로 금지함.** "오늘은 ~알아보겠습니다", "결론적으로", "다양한",
  "~할 수 있습니다" 반복, 교과서식 소제목(~란?/증상/진단/치료), Q&A 블록, 마지막 요약 문단.
- **논문을 별도 "최근 연구" 섹션에서 빼고 이야기 속 근거로 녹임.** 예: "2025년 Frontiers in Medicine에 실린 메타분석을 보면요"
- **진료실 장면은 일반적인 모습으로만 씀.** 특정 환자 사례는 의료광고법상 치료경험담에 해당하기 때문.

| | 전 | 후 |
|---|---|---|
| 제목 | 허리디스크, 다리까지 저리다면 꼭 알아야 할 증상과 치료 이야기 | 허리디스크, 누워 있는 것보다 먼저 알아야 할 것 |
| 첫 문장 | 오늘은 ~ 차근차근 정리해 드릴게요 | "원장님, 디스크라는데 그럼 이제 꼼짝 말고 누워 있어야 하죠?" |
| 소제목 | 허리디스크란? / 증상 / 진단 / 자주 묻는 질문 | 누워만 있는 게 답은 아니더라고요 |

### 5단계. 세부 주제 (검색 의도)

사용자 아이디어: "허리디스크라도 초기 증상이 궁금한 사람, 완치 여부가 궁금한 사람은 니즈가 다르다."

- 처음엔 고정 버튼(초기 증상, 예방법, 완치 여부, 재활 운동 …)으로 만들고, 주제에 따라 논문 검색어도 바뀌게 함.
- "완치 여부"처럼 광고 금지 단어가 들어간 검색어는 질문 형태로만 쓰고 효과를 약속하지 않게 함.
  → 결과 제목: *허리디스크 완치 여부, 제가 "네"라고만 답하지 않는 이유*

### 6단계. 세부 주제 자동 추천

사용자가 가져온 설계안: 네이버 자동완성 10개 수집 → LLM으로 핵심 주제 3개와 H2 목차 생성 → 주제별 PubMed 영문 쿼리 생성.

검토 후 이렇게 바꿔서 구현했습니다.

- **LLM 호출 3번을 1번으로.** 주제 3개 + 검색 의도 + PubMed 검색식을 JSON 스키마로 한 번에 받음. 가벼운 모델(Haiku) 사용.
- **H2 목차 생성은 뺌.** 목차를 먼저 정하면 글이 다시 보고서체로 돌아가기 때문. 흐름은 글을 쓰는 Claude가 짬.
- **주제는 사람이 고름.** 자동완성에 "군복무중허리디스크" 같은 병원과 무관한 주제도 섞여 있어서,
  Claude가 걸러낸 3개를 카드로 보여주고 원장이 클릭. "전반"과 "직접 입력"도 가능.
- 영문 PubMed 검색어 입력칸이 없어짐. 질환 영문명과 검색식을 자동 생성.

실제 결과 (허리디스크):

```
자동완성: 수술, 치료, 원인, 증세, 군복무중허리디스크
추천:     증세 / 치료 / 원인   (군복무중은 제외됨)
검색식:   lumbar disc herniation AND (symptoms OR clinical presentation OR signs)
제목:     허리디스크 증세, 허리보다 다리가 먼저 알려줍니다
```

## 순위 증명·추적

- **순위 증명**: 상위글 분석 표 아래 버튼. 네이버 모바일 통합검색·모바일 블로그탭·PC 블로그탭을 실제 브라우저(Playwright)로 열어 캡처하고, 분석한 순위와 대조합니다. 캡처와 기록은 `proofs/`에 쌓입니다.
- **순위 추적**: 왼쪽 「순위 추적」 칸에 키워드를 넣으면 매일 오전 9시에 1~10위를 캡처해 날짜별 표로 보여 줍니다.
  - 예약 작업 등록: `powershell -ExecutionPolicy Bypass -File track_task.ps1` (PC가 꺼져 있었으면 켜진 뒤 바로 실행)
  - 지금 한 번 돌리기: `.venv\Scripts\python -m services.tracker` · 실행 기록은 `track.log`
  - 추적 이미지는 60일 뒤 지우고 순위 기록(JSON)은 남깁니다.
  - 처음 설치한 PC에서는 `.venv\Scripts\python -m playwright install chromium`이 필요합니다.

## 알려진 한계

- 네이버 자동완성은 공식 API가 아닙니다. 막히면 후보가 비고, Claude가 흔한 주제로 채웁니다.
- Claude Code 구독 경로는 세부 주제 추천에 25~45초, 글 생성에 약 1분 걸립니다.
- 생성된 글은 게시 전에 반드시 의료진이 내용을 확인해야 합니다.
